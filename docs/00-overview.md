## 화면

목록 · 넣기 · 상세 · 할 일, 총 4종.

- 배치와 요소 이름은 `docs/화면구성.pdf` 를 따른다.
- 요소 id 는 그 파일에 적힌 그대로 쓴다.
- (현재 `docs/화면구성.pdf` 가 폴더에 없다. 파일이 추가되기 전에는 id 를 확정하지 않는다.)

### 디자인

- UI 는 맥OS 스타일로 한다.
- CSS 라이브러리는 Tailwind 를 쓰고, 깔끔하고 모던하게 만든다.

## 왜 이렇게 나누는가

관심사 분리 원칙에 따라 한 문서와 한 코드 영역이 한 가지 질문에만 답하도록 나눈다.

- 문서: 무엇을(01) / 어떻게 동작해야 하는가(02) / 어떻게 만들 것인가(03) / 무엇을 할 것인가(04) / 어떤 규칙으로 쓸 것인가(05). 한 가지가 바뀌면 해당 문서만 고치면 되고, 문서 간 충돌도 어느 문서가 우선인지 쉽게 가린다.
- 코드: 백엔드(`backend/`)는 데이터와 규칙, 프론트(`frontend/`)는 화면과 상호작용만 맡는다. 둘은 `/api/` 경로로만 만난다. 그래서 한쪽을 바꿔도 다른 쪽이 영향을 덜 받아 유지보수가 쉽다.
